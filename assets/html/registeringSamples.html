Registering Samples

Registering samples ties a specific crystal, in a specific puck position, to a protein and a shipment. Before you start, make sure you have:

  1. A registered account and proposal access
  2. A shipment created (see Create a Shipment)
  3. A registered, approved protein (see Registering a Protein)
  4. Then: register your samples, as described below

Container setup

Choose a container type — typically a puck — and select from your registered containers in the dropdown. You can optionally choose an autoprocessing pipeline for priority handling of that container's data.

Basic fields

At minimum you need the protein acronym and name for each position. Optional fields include a barcode, comments, and anomalous scatterer information for phasing pipelines.

Extra fields

Additional per-sample metadata beyond the basics — useful for more detailed tracking or downstream processing.

Unattended / automated fields

Parameters used for unattended and automated data collection with MXCuBE3, once enabled on your beamline.

Screenshot needed The sample table for a puck, with the Basic / Extra Fields / Unattended tabs

Cloning and bulk entry

You can clone an existing sample entry to speed up filling a puck with related samples, or upload a larger set of samples at once via a CSV file. Validation errors show up as red text boxes next to the affected field and clear automatically once corrected.
